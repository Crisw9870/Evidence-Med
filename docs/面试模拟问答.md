# 一、项目介绍与模型选型

## 简单介绍最近做的项目，以及你负责哪些工作

> 我最近做的是 Evidence\-Med，基于 Qwen2\.5\-7B\-Instruct 构建证据可追溯的医疗问答模型。主要解决两个问题：一是模型回答中的证据无法核验，二是信息不足时容易过度断言。  
> 
> 我负责从数据构造到评测的完整链路。首先从 Huatuo\-Lite 的 40 多万条医疗问答中选取 1 万条进行 Teacher 蒸馏，设计包含证据充分性、原文证据、关键证据、缺失信息、临床推理和最终回答的 Evidence Schema，并完成自动审计。  
> 
> 然后使用 LoRA 完成 Evidence\-SFT，Schema 合法率达到 99\.55%，Evidence Grounding 达到 98\.68%，CMB\-Exam 提升至 77\.38%。  
> 
> 在此基础上，我又构建 Answer\-level DPO，只优化临床推理和最终回答，通过匿名 A/B、换位复评和置信度门禁，从 9,599 条 Judge 记录中筛选出 3,000/200 条训练和验证偏好对。最终 DPO 验证偏好准确率达到 88\.12%，CMB\-Clin 净胜率提高约 15%，同时医学知识能力基本保持。
> 
> 

---

## 项目里真正和算法相关的工作有哪些？

> 算法相关工作主要有四部分。  
> 
> 第一是任务建模。我将医疗问答拆成任务类型、证据充分性、原文证据、关键证据、缺失信息、临床推理和最终回答。关键证据采用反事实定义：删除该最小证据片段后，如果诊断方向、回答范围或充分性明显改变，才标记为 critical。  
> 
> 第二是数据算法，包括候选筛选、稳定哈希去重、Teacher 蒸馏、证据 span 定位和 accepted/review/rejected 三级审计。  
> 
> 第三是训练算法，包括 LoRA\-SFT、prompt loss mask，以及 Answer\-level DPO。DPO 中冻结 Evidence 结构，只允许回答字段变化，以隔离偏好信号。  
> 
> 第四是评测算法，包括 exact span F1、boundary\-compatible F1、grounding、Macro\-F1、配对 McNemar、换位一致性和模型 Judge 的置信度裁决。
> 
> 

---

## 为什么选择 Qwen2\.5\-7B\-Instruct？模型选型考虑什么？

> 选择 Qwen2\.5\-7B\-Instruct，主要是在中文能力、结构化输出能力、训练成本和部署生态之间做平衡。  
> 
> 项目以中文医疗问答为主，Qwen 的中文理解、指令跟随和 JSON 生成能力比较适合。7B 模型又能在现有 GPU 上完成 LoRA 训练、批量推理和多轮评测，方便快速迭代。  
> 
> 另外，它对 Transformers、PEFT、TRL 和 vLLM 的支持比较成熟，adapter 训练、合并、量化和部署链路完整。项目重点是验证 Evidence 数据和偏好优化方法，因此选择能力足够且成本可控的 7B 模型，比直接使用更大模型更适合做受控实验。
> 
> 

一般选型因素包括：

- 目标语言和领域能力；

- 指令跟随及结构化输出能力；

- 上下文长度和 tokenizer；

- 显存、吞吐和推理延迟；

- LoRA、量化和部署生态；

- License；

- 目标验证集上的 baseline。

需要主动说明：

> 项目没有完成多个基座模型的系统 bake\-off，因此这是工程选型，不能宣称 Qwen2\.5\-7B 一定是所有候选中的最优模型。
> 
>

## 项目用了什么规模的 SFT 数据？

> 原始 Huatuo\-Lite 数据有 409,048 条。项目没有直接继续使用全部数据训练，而是从中选取 10,000 条适合证据抽取的医疗 QA，进行并发 Teacher 蒸馏和审计。  
> 
> 最终获得 8,995 条有效 Evidence 数据，其中训练集 7,671 条、验证集 880 条、独立测试集 444 条。  
> 
> 后续 DPO 从 9,599 条 Judge 记录中筛选出 3,000 条训练 pair 和 200 条验证 pair。DPO 数据规模更小，但每一对都经过结构隔离、置信度门禁和换位一致性筛选。
> 
> 

如果追问 token 数：

> 当前实验报告主要按样本数统计，SFT 最大序列长度为 1,536。准确 token 总量应从预处理数据或训练日志统计，我不会根据样本数直接估算后当成实验结果。
> 
>

# 二、数据构造与监督信号

## 训练数据怎么构造和清洗？怎么判断合成数据的质量以及是否可用？

> 数据构造分为候选筛选、Teacher蒸馏、自动审计和训练导出四步。  
> 
> 第一步，从Huatuo\-Lite中筛选包含患者信息、症状、时间、检查和明确问题意图的病例型问答，过滤纯知识问答、医院推荐、内容过短和缺乏病例事实的数据，并对规范化问题去重。  
> 
> 第二步，使用Teacher模型生成Evidence\-SFT v2\.2格式的结构化标签，包括任务类型、问题意图、证据充分性、原文证据、关键证据、缺失信息、临床推理和最终回答。  
> 
> 第三步，对Teacher输出进行自动审计。检查JSON、Schema、证据原文定位、critical ID一致性、证据重叠、病例外数字、无依据强断言以及是否复制原答案，并分成accepted、review、rejected。  
> 
> 第四步，只将accepted数据导出成ShareGPT风格JSONL，最终得到7,671条训练数据、880条验证数据和444条独立测试数据。
> 
> 

我把质量检查分成硬门禁、语义一致性和分布质量三个层次。

硬门禁包括：

- 输出能否解析成完整JSON；

- 必需字段是否齐全；

- 枚举值是否合法；

- evidence span是否逐字出现在病例中；

- evidence ID是否唯一；

- critical ID是否存在且与importance一致；

- 是否出现空回答、复制原答案等问题。

语义一致性包括：

- `sufficient`是否有足够证据；

- `partial/insufficient`是否说明缺失信息；

- clinical reasoning的结论强度是否与sufficiency一致；

- 是否新增病例外剂量、数值、阈值；

- evidence role是否超出该span能支持的范围。

分布质量包括：

- 科室和任务类型覆盖；

- train/validation/test是否病例隔离；

- sufficiency类别是否失衡；

- 长度分布和截断比例；

- 重复与语义近重复。

> 自动审计主要保证结构和原文忠实性，医学正确性仍需要模型 Judge 和医生抽检。
> 
>

## 数据集怎么划分？如何避免数据泄漏？

> 项目是在 Teacher 蒸馏前完成数据划分。首先根据规范化后的原始问题生成稳定 source\_id，再使用 source\_id 和固定 seed 做哈希分桶，划分 train、validation 和 test。  
> 
> 这样同一个病例后续产生的 Teacher 标签、Mask 变体和 DPO pair 都会继承父 source 的 split，不会因为生成了多个版本而跨集合泄漏。
> 
> 

具体措施包括：

- 原始问题规范化去重；

- 使用稳定 source\_id，而不是文件行号；

- 先划分，再进行蒸馏和数据增强；

- 派生样本继承 parent split；

- DPO 按病例 source 隔离；

- train/validation 病例交叉为 0；

- held\-out test 冻结，不用于调参；

- 保存来源清单和摘要，防止数据池被静默替换。

限制也要说明：

> 文本级去重不能完全排除语义近重复和预训练污染。进一步可以增加 embedding 近邻去重、病例实体级分组和 benchmark contamination 检查。
> 
> 

---

## SFT 数据是什么结构？监督信号是什么？

> SFT 数据采用 ShareGPT 风格的 conversations。human 部分包含任务说明和病例原文，gpt 部分是完整的 Evidence JSON。
> 
> 

输出字段包括：

- `task_type`

- `query_intent`

- `evidence_sufficiency`

- `evidence`

- `critical_evidence_ids`

- `missing_information`

- `clinical_reasoning`

- `final_answer`

> 监督信号（损失函数计算时的目标值）本质上是 causal language modeling 的 token\-level cross entropy。
> 
> 训练时通过 teacher forcing 预测下一个 token。prompt 部分的 label 设置为 `-100`，不参与 loss；assistant 输出的 JSON token 和 EOS 参与 loss。  
> 
> 当前不是为分类、证据抽取和最终回答分别设计独立 loss，而是把完整结构作为统一生成目标进行监督。
> 
>

# 三、模型评测

## 微调完成后，从哪些角度评估模型？

> 我把评测分为五层。  
> 
> 第一层是格式能力，包括 Strict JSON、可恢复 JSON、Schema 合法率和字段一致性。
> 第二层是证据忠实性，包括 grounding、exact span F1、boundary\-compatible F1 和 critical evidence 一致性。
> 第三层是任务判断，包括 task type 和 evidence sufficiency 的 Accuracy、Macro\-F1、Balanced Accuracy 和混淆矩阵。
> 第四层是医学知识保持，使用 CMB\-Exam。
> 第五层是临床回答偏好，使用 CMB\-Clin，对完整性、相关性、医学专业性、安全错误、A/B 换位一致性和净胜率进行评估。  
> 
> 最终 checkpoint 不是只看训练 loss，而是同时满足结构、证据、临床回答质量和医学知识非退化。
> 
> 

---

## 没有唯一标准答案的任务怎么评测？

> 我会把评测拆成客观可验证部分和主观质量部分。  
> 
> JSON 合法性、证据是否来自原文、critical ID 是否一致，可以使用确定性程序指标。  
> 
> 临床推理是否充分、回答是否安全、结论是否克制，没有唯一标准答案，更适合使用带明确 rubric 的 pairwise comparison，让 Judge 或医生比较同一病例下的两个回答。
> 
> 

为了减少偏差：

- 隐藏模型和回答来源；

- 随机化 A/B 位置；

- 交换 A/B 后再次评审；

- 报告换位一致率；

- 设置 hard medical error；

- 同时报告胜、负、平局和 both bad；

- 计算病例级配对置信区间；

- 对安全样本进行医生复核。

> 优化后的 CMB\-Clin 换位一致率超过 80%，DPO 净胜率提高约 15%，因此比单次 Judge 的结果更可信。但模型 Judge 仍不能等同于医生金标或临床正确率。
> 
>

# 四、Bad Case 分析

## 项目遇到哪些 Bad Case？如何定位是数据、模型还是生成策略问题？

> 项目中的主要 Bad Case 包括 evidence 边界过长或过短、证据充分性类别不平衡、信息不足时结论过度确定、回答新增病例外数字，以及早期 DPO Judge 的位置偏差和长度偏好。  
> 
> 我一般按固定顺序定位：首先固定模型、prompt 和 greedy decoding 复现；然后检查原始数据、Teacher 标签和评测 gold；接着比较 Base、SFT、DPO 多个 checkpoint；最后固定模型，只修改温度、最大生成长度和 prompt。
> 
> 

判断标准：

- 标签错误、病例信息缺失、领域覆盖不足：数据问题；

- 不同解码配置下稳定出错，针对性训练后改善：模型能力问题；

- 对温度、长度、采样 seed 高度敏感：生成策略问题；

- 回答合理但 exact match 或 Judge 判错：评测问题。

如果某个垂直领域 Bad Case 更多：

> 我会先比较单位样本错误率，而不是只看绝对数量。然后按科室、任务类型、sufficiency、病例长度和错误标签分桶。确认是覆盖不足后，再补边界样本和 hard examples，并保证新增数据按 source 重新去重和划分，不能把原 test Bad Case 加入训练后继续在原 test 上汇报。
> 
> 

项目中的迭代例子：

- 通过 Atomic Evidence 和 Minimal Critical Span 改善证据粒度；

- 针对 sufficiency 不平衡分析各类别 recall，而不是只看 accuracy；

- DPO 冻结 Evidence 结构，防止偏好训练改变证据标签；

- 使用匿名 A/B、换位复评和置信度门禁，把 CMB\-Clin 换位一致率提升到 80%以上。

# 五、幻觉与生成问题

## 模型为什么会产生幻觉、过度推理或回答冗长？

> 根本原因是语言模型优化的是下一个 token 的概率，而不是真实性。当病例信息不足、训练数据存在强断言，或者模型语言先验强于输入证据时，就可能生成听起来合理但没有来源的内容。  
> 
> 过度推理是因为训练通常只监督整段输出，没有判断每一步推理是否必要、是否受到证据支持。  
> 
> 回答冗长还可能来自 Teacher 风格、Prompt 要求和偏好数据中的长度偏置。如果 Judge 更容易给长回答更高的完整性分，DPO 就可能学到“更长更好”。
> 
> 

处理方式：

- 证据优先生成；

- 信息不足时明确停止推断；

- 使用 sufficiency 控制结论强度；

- 对 DPO pair 做长度匹配；

- Judge 明确惩罚无信息增量的扩写；

- 设置字段长度预算和停止条件；

- 同时报告回答长度和长度归一化指标。

---

## 多模态模型产生幻觉的主要原因是什么？

> 我的项目是纯文本医疗问答，没有实际训练多模态模型。对于多模态幻觉，我的理解主要包括：视觉编码器丢失细粒度信息、图文配对数据存在噪声、视觉投影层对齐不足、OCR 或目标定位失败，以及语言模型先验压过视觉证据。  
> 
> 这和我的项目有相似之处，都是生成结论没有被输入证据充分约束。区别是文本证据可以通过 span grounding 自动验证，多模态则需要区域定位、OCR 对齐或视觉证据引用机制。
> 
> 

---

## 项目中的幻觉怎么检测和处理？

> 我把幻觉分成三类。  
> 
> 第一类是证据幻觉，即 evidence span 不在病例原文中，通过字符串和 offset 定位检测。
> 第二类是结构逻辑幻觉，例如 critical ID 不存在、`sufficient` 没有证据，通过 Schema 和字段一致性规则检测。
> 第三类是回答内容幻觉，例如新增剂量、阈值、数字、无证据强诊断和治疗建议，通过数字审计、强断言规则和模型 Judge 检测。
> 
> 

处理方式：

- 硬错误进入 rejected；

- 可疑样本进入 review；

- 不合格数据不参与训练；

- DPO 任一候选存在硬错误就不导出；

- 推理阶段校验失败时，可重试、降级回答、补充追问或转人工。

> Grounding 能严格检测“证据是否来自输入”，但不能完全判断最终医疗结论是否正确，因此不能把 98\.68% Grounding 说成 98\.68% 临床准确率。
> 
> 

---

## 除了重新生成，还有哪些手段降低幻觉？

> 可以从生成前、生成中和生成后三层处理。  
> 
> 生成前可以使用 RAG、输入质量检查和缺失信息追问。
> 生成中可以使用 JSON Schema、约束解码、较低温度和 evidence\-first 生成。
> 生成后可以使用 grounding verifier、数字和剂量校验、事实一致性检查，以及风险阈值决定是否降级或转人工。  
> 
> 项目中实际实现的是原文证据约束、Schema 审计、关键证据一致性、无来源数字检查、sufficiency 和 missing information。RAG 与线上约束解码属于后续工程方案，不能说成已经完成。
> 
>

# 六、遗忘与后续优化

## 微调后是否出现能力下降？如果结构正确但灾难性遗忘怎么办？

> 项目的出发点之一，就是使用 Huatuo\-Lite 全量数据微调后，模型在 CMB\-Exam 上出现准确率下降。说明数据规模大不等于训练效果一定更好，低质量或高度同质的数据可能改变模型原有能力分布。  
> 
> 后续我改为从 40 多万条数据中选取 1 万条高质量 Evidence 数据，并采用 LoRA 控制参数更新。Evidence\-SFT 的 CMB\-Exam 最终达到 77\.38%，相对目标基线提升约 4\.45%。DPO 后为 77\.33%，相对 SFT 只下降约 0\.05%，没有观察到明显的医学知识退化。
> 
> 

如果真的发生灾难性遗忘，可以：

- 混入通用或医学知识 replay 数据；

- 降低学习率和 epoch；

- 使用 LoRA、冻结更多参数；

- 加入对基座模型的 KL 约束；

- 进行多任务采样；

- 用通用能力指标做早停和 checkpoint 选择。

需要谨慎表述：

> 当前验证的是医学知识保持，不能外推为数学、代码和通用推理等所有能力都没有下降。
> 
> 

---

## 继续增加 SFT 数据收益越来越小时，下一步怎么优化？

> 我不会继续无差别堆数据，而是先画 learning curve，并分析剩余错误集中在哪些区域。  
> 
> 如果是类别不平衡，就补少数类和决策边界样本；如果是信息缺失场景中过度确定，就使用 Evidence Mask 反事实增强；如果格式已经稳定但回答偏好仍有问题，就做 Answer\-level DPO；如果问题来自外部知识缺失，更适合使用 RAG；如果只是 JSON 格式问题，则优先考虑约束解码，而不是继续训练。  
> 
> 本项目 Schema 已达到 99\.55%，继续加入大量同分布格式数据的收益有限，因此后续重点转向高质量回答偏好和临床安全性。
> 
> 

---

## 什么情况下仅靠 SFT 难以提升，需要强化学习或 DPO？

> 项目使用的是 DPO，属于离线偏好优化，不是 PPO 那种在线强化学习。  
> 
> 当模型已经具备稳定的基本能力，但多个答案都合理，难以给出唯一标准 target，而我们更关注完整性、安全性、谨慎程度和结论强度时，SFT 会比较受限。这时如果有可靠的 chosen/rejected 数据，可以使用 DPO。  
> 
> 引入 DPO 的前提是基础格式已经稳定、偏好差异可解释、Judge 足够可靠、reference model 正确，而且有独立外部评测。
> 
> 

结合项目：

> Evidence\-SFT 的 Schema 和 Grounding 已经稳定，所以我冻结 Evidence 字段，只优化临床推理和最终回答。经过换位复评和一致性筛选后，CMB\-Clin 换位一致率超过 80%，DPO 净胜率提高约 15%，CMB\-Exam 只下降约 0\.05%，说明偏好优化改善了回答质量，并基本保持了医学知识能力。
> 
>

# 七、业务价值

## 离线指标提升后，怎么判断是否真正帮助下游业务？

> 离线指标提高只能说明模型更符合当前评测目标，不能直接证明业务价值。需要先建立离线指标与业务行为之间的映射，再通过医生盲评、shadow test 或小流量 A/B 验证。
> 
> 

可以这样映射：

实际验证流程：

1. 医生盲评回答接受率、修改率和严重错误率；

2. Shadow test，不直接影响用户决策；

3. 统计医生完成病例所需时间和证据核查时间；

4. 满足安全门槛后再做小流量 A/B；

5. 如果业务指标提高但 hard error 上升，仍然不能上线。

> 当前项目完成的是离线算法验证。可以说结构化证据具有降低核查成本和支持风险控制的潜力，但不能宣称已经证明真实医疗业务收益。
> 
> 

## 最后需要避免的四种错误表述

- 98\.68% Grounding 不等于 98\.68% 医疗正确率。

- 88\.12% 偏好准确率不等于 88\.12% 临床准确率。

- CMB\-Exam 基本保持不等于所有通用能力都没有下降。

- CMB\-Clin 的模型 Judge 结果比优化前可靠，但仍不等于医生金标。
