# Evidence-SFT 后续实验指导

> 文档定位：项目后续实验的总路线说明。  
> 本文只规定“为什么做、比较什么、如何判断结果”，不展开具体训练命令。  
> 项目来源：参考 EviMask-MedCoT 的“原文证据绑定、关键证据遮蔽、Answer-level DPO”路线，并结合当前项目的数据协议、验证器和模型训练链路进行改造。

## 1. 当前项目已经完成什么

当前项目已经形成以下基础能力：

1. 使用改进后的 system prompt 和 deepseek-v4-flash 构造 10,000 条 teacher 数据；
2. 建立 accepted、review、rejected 三路自动验证流程；
3. 获得 8,995 条 accepted 数据，其中 train 7,671、validation 880、test 444；
4. 在已有全量医学 SFT LoRA 上继续完成 Evidence-SFT；
5. 完成 444 条 held-out Evidence 自动评测；
6. 完成 Base、全量 SFT、Evidence-SFT 三组医学 C-Eval；
7. 证明当前模型具有较稳定的 JSON、Schema 和证据原文引用能力，同时没有观察到明显的医学知识遗忘。

当前主模型训练链路为：

```text
Qwen2.5-7B-Instruct
        ↓
全量医学 SFT LoRA
        ↓
Evidence-SFT
```

接下来不再以“继续堆训练阶段”为目标，而是围绕三个可以被实验回答的问题推进。

---

## 2. 后续实验要回答的三个核心问题

### 问题一：前置全量医学 SFT 是否必要

需要比较：

```text
Base → Evidence-SFT
```

与：

```text
Base → 全量医学 SFT → Evidence-SFT
```

目标是判断 Evidence 能力主要来自 Evidence 数据本身，还是依赖前置全量医学 SFT。

### 问题二：关键证据 Mask 是否改善证据缺失场景

需要通过遮蔽病例中的 critical evidence 构造反事实病例，检查模型能否在决定性证据消失后：

- 降低诊断和处理建议的确定性；
- 不继续引用已被遮蔽的证据；
- 明确指出还缺少什么信息；
- 避免沿用原病例中的确定结论。

目标不是继续提高 JSON 合法率，而是提升模型对“证据是否足够”的敏感性。

### 问题三：DPO 是否能改善最终回答质量

在 SFT 和 Mask 数据增强完成后，构造同一病例下的 chosen/rejected 回答，使用 Answer-level DPO 优化：

- 回答完整性；
- 证据忠实性；
- 信息不足时的安全保守性；
- 最终用户可见回答的质量。

DPO 的目标不是重新学习 JSON 格式，而是在结构能力已经稳定的基础上优化回答偏好。

---

## 3. 总体实验路线

推荐按以下顺序执行：

```text
阶段 A：补齐基础对照
    Base → Evidence-SFT
            ↓
    四组模型统一评测

阶段 B：关键证据 Mask
    构造 masked train / validation / test
            ↓
    无 Mask SFT vs 有 Mask SFT

阶段 C：Answer-level DPO
    构造同 prompt 的 chosen / rejected
            ↓
    最佳 SFT 模型 vs DPO 模型

阶段 D：统一分析
    Evidence + Mask + DPO + C-Eval
            ↓
    确定最终模型和项目结论
```

优先级为：

1. Base 直接进行 Evidence-SFT；
2. 关键证据 Mask 消融；
3. Answer-level DPO；
4. 其他细节消融仅在主实验完成后考虑。

## 4. 实验 A：Base 直接进行 Evidence-SFT

### 4.1 实验目标

回答：**前置全量医学 SFT 对 Evidence 能力是否有必要。**

这个实验同时具有两个意义：

- 复现源项目从 Base 直接进行 Evidence SFT 的基本路线；
- 验证当前项目增加“全量医学 SFT 前置阶段”的改造是否有效。

### 4.2 实验分组

| 编号 | 模型链路 | 当前状态 | 主要作用 |
|---|---|---|---|
| E0 | Base | 已有 C-Eval | 原始能力基线 |
| E1 | Base → 全量医学 SFT | 已有 C-Eval | 普通医学 SFT 基线 |
| E2 | Base → Evidence-SFT | 待训练 | 源项目式直接训练路线 |
| E3 | Base → 全量医学 SFT → Evidence-SFT | 已训练 | 当前改造路线 |

### 4.3 控制变量

E2 和 E3 的 Evidence 阶段必须尽可能保持一致：

- 使用相同 train、validation、test；
- 使用相同 batch size 和 gradient accumulation；
- 使用相同 epoch 或 optimizer steps；
- 使用相同 learning rate、warmup 和 weight decay；
- 使用相同 max sequence length；
- 使用相同 seed；
- 使用相同 LoRA rank、alpha、dropout 和 target modules；
- 使用相同 assistant-only loss 设置；
- 使用相同 checkpoint 选择规则和推理参数。

唯一核心差异应是：

- E2 从 Base 新建 LoRA；
- E3 从已有 `sft-base` LoRA 继续训练。

特别注意：训练脚本新建 LoRA 时默认 rank 为 8，而现有 `sft-base` 的 rank 为 16。E2 必须显式使用 rank 16，否则会同时改变初始化路径和 LoRA 容量，导致对比不公平。

### 4.4 评测要求

E0、E1、E2、E3 都应使用同一套 444 条 Evidence test 评测。当前 E0、E1 尚未补 Evidence 评测，需要让 evaluator 支持：

- 只加载 Base；
- 加载 Base + 指定 adapter。

E2 还需要补跑与其他模型相同设置的 C-Eval。

### 4.5 主要指标

主要看以下三类指标：

1. 结构能力：Strict JSON、Schema valid；
2. Evidence 能力：grounding、boundary-compatible match、critical evidence teacher agreement；
3. 医学知识保护：C-Eval。

`evidence_sufficiency` 不再使用总体 accuracy 作为主要指标，应使用各类别 recall、macro-F1 或 balanced accuracy，并同时报告 majority-class baseline。

### 4.6 不同结果如何解释

#### E2 与 E3 基本一致

说明 Evidence 数据本身已经足以训练结构化证据能力，前置全量医学 SFT 不是必要条件。此时 E2 路线更简单，E3 可以作为两阶段训练对照。

#### E2 格式接近，但推理或 C-Eval 弱于 E3

说明 Evidence 数据主要负责结构学习，全量医学 SFT 为临床表达和知识保持提供了基础。此时两阶段训练路线得到支持。

#### E2 明显优于 E3

说明前置全量 SFT 可能对 Evidence 任务产生干扰。后续 Mask 和 DPO 实验应优先从 E2 开始。

### 4.7 阶段交付物

- 一个独立的 Base→Evidence LoRA；
- E0～E3 的统一 Evidence 指标表；
- E0～E3 的 C-Eval 对照表；
- 一段关于“前置全量 SFT 是否必要”的结论。

推荐输出目录：

```text
outputs/evidence-sft-from-base
results/evidence_eval_base
results/evidence_eval_sft_base
results/evidence_eval_from_base
```

## 5. 实验 B：关键证据 Mask 数据增强与消融

### 5.1 这里的 Mask 是什么

本阶段的 Mask 指：**将病例中的关键诊断证据遮蔽或删除，构造证据缺失的反事实病例。**

它与训练代码中的 `train_on_inputs` loss mask 不是同一概念。后者只是决定是否对输入 token 计算训练损失，不是当前项目的核心 Mask 实验。

### 5.2 实验目标

回答：**关键证据消失后，模型能否正确降低结论确定性。**

当前原始 Evidence test 主要验证模型能否从已有病例中抽取证据，但不能充分验证模型在证据缺失时是否会继续过度诊断。Mask test 正好补上这部分。

### 5.3 Mask 数据的构造原则

候选样本至少需要满足：

- 已通过 accepted 验证；
- 包含明确的 `critical_evidence_ids`；
- critical span 可以在病例原文中唯一定位；
- 遮蔽后不会造成无法理解的严重语法破坏；
- 被遮蔽内容确实会改变证据充分性或回答确定性。

基本流程：

```text
Accepted 原始样本
        ↓
定位 critical evidence spans
        ↓
生成 masked 病例
        ↓
teacher 根据 masked 病例重新生成完整 JSON
        ↓
现有 validator 再次校验
        ↓
形成 masked train / validation / test
```

只删除原病例中的 span 不足以得到新的训练目标。Mask 后以下字段通常都需要重新生成或更新：

- `evidence_sufficiency`；
- `evidence`；
- `critical_evidence_ids`；
- `missing_information`；
- `clinical_reasoning`；
- `final_answer`。

### 5.4 数据泄漏要求

同一个原始病例及其所有 Mask 版本必须属于同一个 split。

禁止出现：

```text
原始病例进入 train
Mask 版本进入 test
```

Mask train 只能来自当前 train；Mask validation 只能来自 validation；Mask test 只能来自当前 444 条 test。

### 5.5 实验分组

从实验 A 中表现更合适的初始化路线出发，建立：

| 编号 | 原始 Evidence 数据 | Mask 数据 | 作用 |
|---|---:|---:|---|
| M0 | 有 | 无 | 无 Mask 对照 |
| M1 | 有 | 有 | Mask 数据增强模型 |

M0 可以复用实验 A 中对应的模型，不需要重复训练。

### 5.6 公平性控制

M1 加入 Mask 数据后，数据量会增加。如果 M0 和 M1 都简单训练相同 epoch，M1 会得到更多 optimizer updates，结果会混入“训练更久”的影响。

因此 Mask 消融优先固定：

- 总 optimizer steps；
- batch 与梯度累积；
- learning rate schedule；
- LoRA 配置；
- 原始数据与 Mask 数据的采样比例。

Mask 数据比例应先根据可用样本质量确定，不必为了追求数量将所有 critical 样本都纳入训练。先确保 Mask 后的病例和目标回答逻辑成立。

### 5.7 Mask 专项评测

Mask test 应独立于原始 444 条 Evidence test。主要评测：

#### 主指标：Mask uncertainty response rate

关键证据被遮蔽后，模型正确转为不确定回答的比例。一个通过样本应至少满足：

- 输出仍为合法 Schema；
- 不再引用被隐藏的证据；
- `evidence_sufficiency` 合理转为 partial 或 insufficient；
- `missing_information` 指出关键缺失内容；
- final answer 不继续维持原有确定结论。

#### 辅助指标

- Mask 后证据 grounding rate；
- Masked evidence leakage rate；
- 过度确定回答率；
- missing information 命中率；
- sufficient、partial、insufficient 各类别 recall；
- 原始 Evidence test 上的性能保持情况。

### 5.8 暂定成功标准

Mask 实验的主要判断不是追求某个固定绝对数字，而是 M1 相对 M0 是否出现稳定、方向明确的提升。

可使用以下暂定标准：

- Mask uncertainty response rate 相对 M0 有明显提升；
- 过度确定回答率明显下降；
- 原始 Evidence grounding 和 JSON 指标下降不超过约 0.5 个百分点；
- C-Eval 不出现超过约 1 个百分点的整体下降。

这些阈值是项目决策用的保护线，不是医学部署标准。若样本量较小，应同时报告变化的实际样本数，避免只看百分比。

### 5.9 不同结果如何解释

#### Mask test 提升，原始能力保持

说明关键证据 Mask 数据增强有效，M1 可以作为后续 DPO 的起点。

#### Mask test 提升，但原始 Evidence 或 C-Eval 明显下降

说明 Mask 数据比例可能过高，模型过度偏向保守回答。应优先调整原始/Mask 采样比例，而不是直接进入 DPO。

#### Mask test 没有提升

优先检查数据构造：遮蔽内容是否真正关键、teacher 是否正确降低确定性、自动指标是否能识别合理的不确定表达。不要立即用更长训练掩盖数据问题。

### 5.10 阶段交付物

- Mask 数据生成与验证流程；
- masked train、validation、test；
- M0 与 M1 的消融结果表；
- 一组典型的“Mask 前、Mask 后、模型回答变化”案例；
- 关于 Mask 是否改善证据缺失场景的结论。

推荐目录：

```text
data/evidence_mask/
outputs/evidence-mask-sft/
results/evidence_mask_eval/
```

## 6. 实验 C：Answer-level DPO

### 6.1 进入 DPO 的前置条件

只有满足以下条件后才进入 DPO：

- Base→Evidence 对照已经完成；
- Mask 消融已经完成；
- 已经确定一个表现最好的 SFT 起点；
- 能为同一 prompt 构造可信的 chosen/rejected；
- 偏好标准可以被清楚解释。

DPO 不是为了增加训练阶段，而是为了解决 SFT 后仍然存在的最终回答质量问题。

### 6.2 DPO 的目标

DPO 重点优化最终用户可见回答：

- 是否直接回答用户问题；
- 是否完整但不过度延伸；
- 是否忠实于当前可见证据；
- 证据不足时是否保守；
- 是否明确指出缺失信息；
- 是否避免无依据的诊断和处理建议。

JSON 格式、evidence span 和 critical ID 已经由 SFT 学习，不应成为 DPO 的主要目标。

### 6.3 偏好对的基本形式

DPO 必须使用同一 prompt 下的成对回答：

```text
prompt: 同一个原始或 Mask 病例
chosen: 更完整、忠实、安全的回答
rejected: 过度确定、不完整或与证据不符的回答
```

当前 accepted/review/rejected 是数据行质量分流，不能直接当作 DPO chosen/rejected，因为它们通常不是同一 prompt 的回答对。

### 6.4 偏好对来源

可采用以下路线：

1. 使用最佳 SFT 模型对同一 prompt 生成多个候选回答；
2. 使用自动规则先筛除 JSON 损坏、证据不落原文等明确错误；
3. 使用 teacher 或 LLM Judge 比较剩余候选；
4. 只保留偏好差异清晰的 pair；
5. 对部分 pair 做抽样检查，不做高成本临床认证。

对于 masked prompt，最有价值的 pair 是：

- chosen：承认证据不足并指出缺失信息；
- rejected：继续沿用被遮蔽前的确定诊断或治疗建议。

### 6.5 Answer-level 隔离策略

为了避免 DPO 破坏 JSON 和证据结构，chosen/rejected 应尽量：

- 使用相同 Schema；
- 保持 evidence 等结构字段一致；
- 主要让差异集中在 `clinical_reasoning` 和 `final_answer`；
- 更严格时，只改变 `final_answer`。

这样可以把 DPO 的作用解释为“最终回答偏好优化”，而不是重新学习整个 Evidence 任务。

### 6.6 实验分组

| 编号 | 模型 | 作用 |
|---|---|---|
| D0 | 最佳 SFT/Mask-SFT checkpoint | DPO 前基线 |
| D1 | D0 → Answer-level DPO | 偏好优化模型 |

### 6.7 DPO 主要指标

#### 主指标

- 同一评测集上 D1 相对 D0 的盲评 win rate；
- Mask 场景中的安全保守性 win rate；
- 最终回答完整性和证据忠实性评分。

#### 保护指标

- Strict JSON 和 Schema valid 不应明显下降；
- Evidence grounding 不应明显下降；
- Mask uncertainty response rate 不应下降；
- C-Eval 不应出现明显退化。

LLM Judge 的结果只能称为“模型裁判偏好胜率”，不能称为临床正确率。评测时应交换 A/B 展示顺序，减少位置偏差。

### 6.8 暂定成功标准

DPO 值得保留，需要同时满足：

- D1 对 D0 的盲评 win rate 明确高于 50% 随机基线，项目上可以将约 60% 以上视为较有解释力的提升；
- JSON、Schema、grounding 等结构指标基本保持；
- C-Eval 不出现超过约 1 个百分点的整体下降；
- 提升来自回答完整性、忠实性或安全性，而不是单纯变得更长或更保守。

### 6.9 何时停止 DPO

出现以下情况时不应继续增加 DPO epoch：

- win rate 没有稳定超过基线；
- 回答普遍变长但质量没有提升；
- 模型在信息充分场景中也频繁拒答；
- JSON 或 grounding 明显下降；
- C-Eval 出现明显退化；
- 偏好 pair 本身无法稳定判断 chosen 更好。

此时应回到偏好数据质量，而不是继续调学习率或增加训练时长。

### 6.10 阶段交付物

- DPO chosen/rejected 数据；
- 偏好数据自动验证与 LLM Judge 结果；
- D0 与 D1 的盲评胜率；
- DPO 前后 Evidence、Mask、C-Eval 保护指标；
- 一段关于 DPO 是否带来独立增益的结论。

推荐目录：

```text
data/evidence_dpo/
outputs/evidence-dpo/
results/evidence_dpo_eval/
```

## 7. 全项目统一评测框架

所有模型尽量复用同一套评测，避免每个阶段各自选择有利指标。

### 7.1 结构指标

- Strict JSON valid；
- Recoverable JSON valid；
- Schema valid；
- final answer non-empty；
- critical internal consistency。

### 7.2 证据指标

- evidence span grounding rate；
- sample-level all-grounded rate；
- teacher exact Precision、Recall、F1；
- boundary-compatible Precision、Recall、F1；
- critical evidence teacher agreement。

### 7.3 分类指标

- task type 各类别 recall 和 macro-F1；
- evidence sufficiency 各类别 recall、macro-F1、balanced accuracy；
- majority-class baseline。

不再将 sufficiency 总体 accuracy 单独作为模型亮点。

### 7.4 Mask 专项指标

- Mask uncertainty response rate；
- masked evidence leakage rate；
- 过度确定回答率；
- missing information 命中率。

### 7.5 DPO 专项指标

- DPO vs SFT 盲评 win rate；
- 回答完整性偏好；
- 证据忠实性偏好；
- 安全保守性偏好。

### 7.6 医学知识保护指标

- C-Eval 总分；
- 基础医学、临床医学、医师资格三个子任务；
- 相对 Base、全量 SFT 和 DPO 前 checkpoint 的变化。

由于目前 C-Eval 只有 818 道题，1～3 道题的变化不能解释为显著提升或下降。除百分比外，必须同时报告答对题数变化。

## 9. 模型选择规则

最终模型不能只按一个指标选择，建议遵循以下顺序：

1. JSON、Schema 和 grounding 必须保持稳定；
2. 原始 Evidence test 不能明显退化；
3. Mask test 中的过度确定回答应明显减少；
4. DPO 应带来可解释的回答质量提升；
5. C-Eval 不应出现明显知识遗忘；
6. 当多个模型结果接近时，优先选择训练链路更简单的模型。

可以将最终目标概括为：

> 在保持结构化证据能力和医学知识的前提下，提高模型在关键证据缺失场景中的不确定性表达，并通过 DPO 改善最终回答质量。

## 10. 项目执行中的停止规则

为了控制项目复杂度，以下工作不作为当前主线：

- 不重新处理现有 review/reject 数据；
- 不进行高成本的正式临床人工认证；
- 不因为 1～2 道 C-Eval 差异反复训练；
- 不把训练 loss 当作跨实验的最终能力指标；
- 不把 input-loss mask 与关键证据 Mask 混为一谈；
- 不使用不同 prompt 的数据强行组成 DPO pair；
- 不为了让项目包含 DPO 而使用无法解释的偏好数据。

如果一个实验没有回答新的研究问题，就不继续扩展该实验。
