## 1. 项目概述

### 1.1 项目目标

本项目的目标不是单纯提高医学选择题分数，而是让医疗问答模型在生成结论的同时，**输出可检查、可追踪的结构化证据**，包括：

- 任务类型 (`task_type`)
- 问题意图 (`query_intent`)
- 证据充分性 (`evidence_sufficiency`)
- 原文证据 (`evidence`) - 从病例原文逐字抽取
- 关键证据编号 (`critical_evidence_ids`)
- 缺失信息 (`missing_information`)
- 推理过程 (`clinical_reasoning`)
- 最终回答 (`final_answer`)

### 1.2 输出格式

模型学习输出结构化 JSON：

```json
{
  "task_type": "diagnostic_reasoning",
  "query_intent": ["评估持续干咳的可能病因"],
  "evidence_sufficiency": "partial",
  "evidence": [
    {
      "id": "E1",
      "span": "感冒好了以后",
      "importance": "supporting",
      "role": "提供起病背景"
    },
    {
      "id": "E2",
      "span": "一直干咳，有两个月了",
      "importance": "critical",
      "role": "核心症状，决定诊断方向"
    }
  ],
  "critical_evidence_ids": ["E2"],
  "missing_information": ["胸部影像学检查", "肺功能检查"],
  "clinical_reasoning": "已有证据支持慢性咳嗽需要进一步评估...",
  "final_answer": "根据您描述的情况..."
}
```

### 1.3 JSON 输出的价值

| 价值 | 说明 |
|------|------|
| 可自动验证 | 检查字段完整性、证据是否来自原文、关键证据编号一致性 |
| 可追溯 | 最终回答与引用证据建立明确关系 |
| 可扩展 | 前端按需展示"结论、依据、缺失信息" |
| 可用于风险控制 | 根据 `evidence_sufficiency` 和 `missing_information` 决定是否提示补充信息或转人工 |

## 2. 技术架构

### 2.1 整体流程

```
                  原始医疗 QA
                      │
                      ▼
┌──────────────────────────────────────────────────┐
│  Evidence-SFT 数据构造 (process_sft/)             │
│  候选筛选 → Teacher 蒸馏 → 三级审计 → 导出训练集    │
└──────────────────────┬───────────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────────┐
│  Evidence-SFT 训练 (training/supervised_finetuning.py) │
│  Qwen2.5-7B + LoRA → 学会结构化证据输出            │
└──────────────────────┬───────────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────────┐
│  DPO 偏好优化 (process_dpo/)                      │
│  来源选择 → 候选生成 → 构造 pair → 双向 Judge       │
│  → 严格导出 → DPO 训练                             │
└──────────────────────┬───────────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────────┐
│  评估 (cmb_eval/ + process_sft/evaluate_evidence.py) │
│  Evidence 指标 / CEval / CMB-Exam / CMB-Clin      │
└──────────────────────────────────────────────────┘
```

### 2.2 模型训练路线

#### 路线对比

| 路线 | 名称 | 训练链路 | 产物路径 |
|------|------|----------|----------|
| E2 | Direct | Qwen2.5-7B-Instruct → Evidence-SFT | `outputs/evidence-sft-frombase` |
| E3 | Two-stage | Qwen2.5-7B-Instruct → Full-SFT → Evidence-SFT | `outputs/evidence-sft` |

#### 实验性质

本实验为**初始化路径消融**，而非严格的"医学 SFT 必要性实验"：

- **Direct** 从 Base 新建 LoRA，直接学习结构化证据任务
- **Two-stage** 从已有 Full-SFT LoRA 继续训练，累计保留前置问答训练和 Evidence 训练的更新

#### 关键发现

> **Evidence 数据本身已足以让 Base 模型获得稳定的 JSON、原文证据引用和字段约束能力。前置 Full-SFT 不是形成 Evidence 能力的必要条件。**

## 3. 数据构建

### 3.1 数据来源

- **Teacher 模型：** deepseek-v4-flash（蒸馏生成）
- **原始数据量：** 10,000 条
- **数据验证：** 三级审计（accepted / review / rejected）

### 3.2 数据分流结果

| 数据状态 | 样本数 | 占比 | 用途 |
|----------|--------|------|------|
| Accepted | 8,995 | 89.95% | 训练、验证、测试 |
| Review | 957 | 9.57% | 冻结，不进入训练 |
| Rejected | 48 | 0.48% | 冻结，不进入训练 |
| **合计** | **10,000** | **100%** | - |

### 3.3 Accepted 数据拆分

| 数据集 | 样本数 | 占比 | 用途 |
|--------|--------|------|------|
| Train | 7,671 | 85.28% | 参数训练 |
| Validation | 880 | 9.78% | 训练过程中观察泛化损失 |
| Test | 444 | 4.94% | 训练结束后独立自动评测 |
| **合计** | **8,995** | **100%** | - |

### 3.4 验证器检查项

- 样本 ID 完整性、唯一性和候选集对齐
- JSON 字段和枚举值合法性
- evidence span 是否能在病例原文中定位
- 证据 ID 是否规范、连续，是否存在重复或重叠
- `critical_evidence_ids` 与 evidence 的 `importance` 是否一致
- sufficient/partial/insufficient 与证据、缺失信息之间是否存在明显矛盾

### 3.5 主要 Reject 原因

| 原因 | 数量 |
|------|------|
| evidence span 不在病例原文中 | 38 |
| 充分但无证据 | 8 |
| 最终回答直接复制原答案 | 2 |

### 3.6 数据分布风险

`evidence_sufficiency` 分布高度不均衡：

| 类别 | 样本数 | 占比 |
|------|--------|------|
| partial | 8,841 | 88.41% |
| insufficient | 864 | 8.64% |
| sufficient | 294 | 2.94% |
| conflicting | 1 | 0.01% |

**风险：** 这一分布会自然诱导模型偏向输出 `partial`，是测试集中充分性分类发生类别坍缩的主要背景。

## 4. 模型训练

### 4.1 Evidence-SFT 训练配置

| 配置项 | Direct | Two-stage |
|--------|--------|-----------|
| Base model | Qwen2.5-7B-Instruct | Qwen2.5-7B-Instruct |
| LoRA 初始化 | 新建 LoRA | 恢复 `outputs/sft-base` LoRA |
| Train / Validation | 7,671 / 880 | 7,671 / 880 |
| LoRA rank / alpha / dropout | 16 / 32 / 0.05 | 16 / 32 / 0.05 |
| 单卡 batch / accumulation | 8 / 4 | 8 / 4 |
| 有效 batch size | 32 | 32 |
| Epoch / optimizer steps | 2 / 480 | 2 / 480 |
| Learning rate | 1e-5 | 1e-5 |
| Max sequence length | 1,536 | 1,536 |
| Precision | BF16 | BF16 |
| Gradient checkpointing | 开启 | 开启 |
| Seed | 42 | 42 |

### 4.2 收敛结果对比

| 指标 | Direct | Two-stage | 差异 |
|------|--------|-----------|------|

| Validation perplexity | 1.8434 | 1.8307 | +0.0127 |
| Evidence 训练时间 | 7,079.66 秒 | 7,091.83 秒 | -12.17 秒 |
| 训练吞吐 | 2.167 samples/s | 2.163 samples/s | +0.004 |

### 4.3 验证损失曲线

| Step | Direct | Two-stage | 差异 |
|------|--------|-----------|------|
| 100 | 0.7239 | 0.6807 | +0.0432 |

**结论：** 两路验证损失都持续下降且没有反弹。Two-stage 全程更低，但差距快速收窄，更像前置 Full-SFT 提供了较好的收敛起点。

### 4.4 训练成本对比

| 路线 | 前置训练 | Evidence 训练 | 总墙钟时间 | 总 FLOPs |

### 5.3 CEval 医学知识保持

四组 C-Eval 使用相同的三个医学子任务、相同 5-shot 设置和相同 818 道测试题：

| 模型 | 基础医学 (175) | 临床医学 (200) | 医师资格 (443) | 总计 (818) |
|------|----------------|----------------|----------------|------------|
| Base | 92.00% | 87.50% | 89.39% | **89.49%** |
| Full-SFT | 91.43% | 85.50% | 89.84% | **89.12%** |
| Direct | 89.71% | 88.00% | 89.16% | **89.00%** |
| Two-stage | 90.29% | 86.00% | 90.29% | **89.24%** |

**结论：** 最大差异仅 4/818 题（0.49 pp），未观察到灾难性遗忘，也不支持显著提升。

### 5.4 CMB-Exam：知识保持（四模型对比）

CMB-Exam 使用同一 test 集 11,200 道题：

| 模型 | 正确数 | Accuracy | 相对 Base | 无效输出 |
|------|--------|----------|-----------|----------|
| Base | 8,504 | 75.929% | 0 | 296 |
| Full-SFT | 8,441 | 75.366% | -0.563 pp | 13 |
| Evidence-SFT | 8,667 | **77.384%** | +1.455 pp | 132 |
| Evidence-DPO | 8,661 | 77.330% | +1.402 pp | 136 |

**SFT vs DPO 配对分析：**
- 共同答对：8,622 题
- 共同答错：2,494 题
- DPO 单独答对：39 题
- SFT 单独答对：45 题
- 配对差值 95% CI：**[-0.214, +0.107] pp**
- McNemar p=0.586

**结论：** DPO 通过知识非退化检查，但不能据此宣称 DPO 有效。

### 5.5 CMB-Clin：临床回答质量

CMB-Clin 覆盖 74 个病例、208 个多轮问题，每题由 `mimo-v2.5-pro` 匿名评审两次并交换 A/B 位置：

| 指标 | Evidence-SFT | Evidence-DPO | DPO−SFT |
|------|--------------|--------------|---------|
| 双顺序稳定胜出 | 23 | 28 | +5 题 |
| 平局 / both bad | - | - | 29 / 10 |
| 净胜率 | - | - | +6.25 pp |
| 流畅度 | 4.625 | 4.630 | +0.005 |
| 相关性 | 4.190 | 4.180 | -0.010 |
| 完整性 | 3.452 | 3.558 | +0.106 |
| 医学专业性 | 3.663 | 3.683 | +0.019 |
| hard medical error | 8.17% | 9.86% | +1.68 pp |
| 平均生成 tokens | 228.4 | 255.8 | +27.4 |

**关键问题：**
- **Judge 换位一致率仅 43.27%**（90/208），118 条结论无法复现
- 净胜率 95% CI：**[-12.05, +24.42] pp**，区间跨 0
- DPO 的完整性信号可能被长度增加混淆（+12%）

**结论：** DPO 改变了回答行为，可能轻微提升完整性，但现有实验无法区分小幅真实增益与 Judge 噪声。

## 6. 关键结论

### 6.1 综合能力判断

| 项目目标 | Direct | Two-stage | 判断 |
|----------|--------|-----------|------|
| Strict JSON | 99.77% | 99.55% | ✅ 两路均达成 |
| 完整 Schema | 99.55% | 99.55% | ✅ 两路均达成 |
| 原文证据引用 | 98.68% | 99.05% | ✅ 两路均达成 |
| Critical 内部一致 | 99.55% | 99.32% | ✅ 两路均稳定 |
| Teacher 严格证据边界 | F1 58.10% | F1 59.49% | ⚠️ 部分达成 |
| 边界兼容证据匹配 | F1 83.36% | F1 84.51% | ✅ 两路均较高 |
| Task type | Macro-F1 80.16% | 82.00% | ⚠️ 可用 |
| Evidence sufficiency | Macro-F1 39.10% | 39.60% | ❌ 类别坍缩 |
| 医学知识保持 | C-Eval 89.00% | 89.24% | ✅ 与 Base 持平 |
| DPO 知识保持 | CMB-Exam 77.330% | 77.384% | ✅ 基本不退化 |
| DPO 临床提升 | 净胜率 +6.25 pp | CI 跨 0 | ❌ 未证明 |
| DPO 安全性 | hard error 9.86% | 8.17% | ❌ 未建立 |

**整体评级：** SFT 主实验可 Share with caveats；DPO 模型选择为 Needs revision。

### 6.2 最终模型选择

| 决策 | 模型 | 理由 |
|------|------|------|
| **默认模型** | Evidence-SFT | CMB-Exam 最佳 checkpoint，临床安全证据更保守 |
| **候选模型** | Evidence-DPO | 保留 adapter、训练日志和全部预测，用于后续复核 |

### 6.3 最稳妥的项目结论

> 1. **Evidence 数据本身已足以让 Base 模型获得稳定的 JSON、原文证据引用和字段约束能力。** 前置 Full-SFT 不是形成 Evidence 能力的必要条件。
>
> 2. **Direct Evidence-SFT 足以获得可检查、可追溯的结构化证据能力。** 从零构建时，Direct 的性价比明显更高（成本约为 Two-stage 的 1/10）。
>
> 3. **DPO 训练过程正常收敛，但临床收益尚未证明。** CMB-Exam 显示知识基本不退化，但 CMB-Clin 的净胜率区间跨 0、Judge 换位一致率仅 43.27%。
>
> 4. **不能把 teacher agreement、原文 grounding 或自动 Judge 偏好包装成临床正确率。**

### 6.4 实验限制

1. **训练量不对等：** Two-stage 额外使用 120k 混合数据和 7,500 steps
2. **病例预暴露：** Evidence 数据来自 `medical_100k`，Two-stage 可能在测试前看过同病例原始问答
3. **单次运行：** 两路都只有 seed 42 的一个 checkpoint，没有多 seed 方差
4. **评价目标有限：** 当前配对指标主要反映格式、grounding 和 teacher agreement，而非临床效用
5. **DPO 偏好数据长度倾向：** 81.32% 的 chosen 比 rejected 更长
6. **Judge 稳定性不足：** CMB-Clin 换位一致率仅 43.27%

## 7. 后续建议

### P0：冻结现有模型与结果

- 保留 Direct Evidence-SFT、Evidence-DPO、训练日志、DPO pair audit、CMB 逐题预测和 Judge 原始记录
- **不追加 DPO 训练**：当前停止条件已触发

### P1：优先做安全人工复核

- 复核 CMB-Clin 中任一模型被两个位置共同确认 hard error 的 13 个问题
- **优先处理 DPO 独有的 6 个问题：** `4:1`、`39:0`、`39:1`、`46:2`、`58:1`、`70:1`

### P2：补强不一致 Judge

- 对 118 条换位不一致记录增加第三裁决，或使用第二个固定强 Judge
- **下一次评测前预先定义：**
  1. 病例聚类净胜率 CI 下界不低于 0
  2. 医学专业性与相关性不退化
  3. hard-error 差值满足预设非劣界
  4. CMB-Exam 知识能力下降不超过预设界值
  5. 长度匹配或去冗余敏感性分析仍保持收益

### P3：修复偏好数据的长度混杂

- 下一版数据应在 Judge rubric 中明确区分"覆盖关键内容"与"单纯扩写"
- 报告 chosen/rejected 长度分层
- 优先加入短而正确对长而冗余的反例
- **若没有新的高质量偏好数据，不启动 DPO v2**

### P4：保留 Evidence-Mask 为独立消融

- Evidence-Mask 仍应作为独立实验回答"删除关键证据后，模型能否降低确定性并调整缺失信息"
- 不能混入本轮 DPO 结论

## 附录：面试表述建议

### 项目表述

> 基于 Qwen2.5-7B-Instruct 构建 Evidence-SFT 与 Strict Answer-level DPO 流水线：使用 10k 条 teacher 数据完成 accepted/review/rejected 分流，在 8,995 条 accepted 数据上验证 Direct Evidence-SFT 可达到 99.55% Schema 合法率和 98.68% evidence grounding；进一步构造 1,243/101 个 DPO train/validation pair，并用 CMB-Exam 11,200 题和 CMB-Clin 74 个病例进行外部评测。DPO 的 CMB-Exam 为 77.33%，相对父模型仅 -0.054 pp；Clin 净胜率点估计 +6.25 pp，但换位一致率只有 43.27% 且安全非退化未建立，因此保留 DPO 为候选而不夸大结论。

### 面试时应主动说明

1. 98.68%/99.05% 是"预测证据能否在病例原文逐字找到"，**不是医疗正确率**
2. 58.10%/59.49% 是与 teacher 的严格 span 边界一致性，**不是临床准确率**
3. 两路 sufficiency accuracy 都低于固定预测 `partial` 的 87.61% 基线
4. Two-stage 的小幅优势没有通过多数配对显著性判断，且受到额外训练量与病例预暴露混杂
5. 当前为单 seed 实验；final answer 已有自动 Judge，但换位稳定性不足，且尚无医生金标
6. JSON 是模型输出协议，实际产品会转换成人类可读页面

### 常见问题简洁回答

**为什么要比较 Direct 和 Two-stage？**  
为了判断 Evidence 结构能力究竟来自专门的 Evidence 数据，还是必须依赖前置 Full-SFT。结果显示 Direct 已能达到 99.55% Schema 和 98.68% grounding，说明前置阶段不是必要条件。

**DPO 训练成功了吗？**  
优化过程成功：验证偏好准确率 88.12%，reward margin 0.286。外部效果尚未成功验证：CMB-Exam 证明知识基本不退化，但 CMB-Clin 的净胜率区间跨 0、换位一致率仅 43.27%。

**项目最大的不足是什么？**  
Evidence sufficiency 类别严重不均衡，两路都坍缩到 `partial`；DPO 偏好数据存在明显长度倾向；CMB-Clin 自动 Judge 稳定性不足且没有医生终审，因此最终回答的临床正确性和安全性仍未被可靠验证。
